# Reproducible Provider and Package Artifacts

Phase O3.2 turns the checked GitHub Action, GitLab adapter, and npm archive inventory
into one reviewable release-artifact gate. It detects stale generated bytes without
making GitHub-hosted, GitLab-hosted, registry, or browser claims that the local checks
cannot prove.

That description remains the O3.2 local-artifact boundary. O5.2 later published the
audited npm archive and GitHub Action, and O5.3 independently verified those exact
public bytes in hosted execution. GitLab component/catalog publication and the OCI
image remain withheld, so their local-only boundary is unchanged. See
[Published release verification](published-release-verification.md).

## Canonical contracts

[`../packaging/release/provider-artifact-contract.json`](../packaging/release/provider-artifact-contract.json)
defines both provider distributions, required runtime and legal files, reviewed
metadata inputs, the unprivileged container identity, and the browser-claim boundary.
[`../packaging/release/reproducible-artifacts.json`](../packaging/release/reproducible-artifacts.json)
is the generated byte ledger. It records every ncc loader/chunk, the copied
`libpg-query.wasm` and Cytoscape assets, legal files, complete-distribution
fingerprints, provider metadata hashes, declared toolchain, and the canonical npm
archive identity from `packaging/npm/package-contents.json`.

The private development tree and sanitized public tree have different manifest bytes
by design. `packaging/npm/public-package-contents.json` freezes the latter archive;
the package verifier selects it automatically when the staged manifest omits
`private`. This prevents a public clean clone from either failing on a private-only
assertion or silently accepting a different tarball.

The distribution fingerprint covers the entire directory, not a hand-picked list.
Adding, removing, renaming, or changing any regular file changes the fingerprint.
Required-file and chunk checks additionally make accidental partial publication an
explicit error.

## Maintainer commands

After changing provider entrypoints or imported engine code, intentionally rebuild and
rewrite the reviewed ledger:

```powershell
pnpm run artifacts:write
```

Review every changed generated file and the new ledger. The non-mutating gate builds
both providers again beneath a guarded `.tmp` directory and compares their complete
file records byte for byte with the checked distributions:

```powershell
pnpm run artifacts:check
```

Alternate build output is accepted only below the repository `.tmp` directory. The
shared provider recipe owns the ncc flags and all copied runtime/legal assets, so the
GitHub and GitLab builders cannot silently diverge.

## Controlled GitHub Action smoke

`pnpm run action:controlled-smoke` creates two isolated temporary Git repositories
from frozen `.ts.txt` fixtures, prepares lifecycle-disabled local-only dependencies,
and executes the checked `action-dist/index.js`. It proves a real baseline/candidate
scan, an added `POST /controlled-orders` endpoint, summary generation, all ten result
artifacts, and an exact distribution fingerprint in the scan recipe.

The target fixture never contains the action implementation. This prevents the test
from accidentally proving that candidate-controlled action code can analyze itself.
The smoke does not emulate the composite upload step or upgrade the separately
retained GitHub-hosted validation claim.

## npm clean-room smoke

The canonical npm file/size/hash manifest remains
`packaging/npm/package-contents.json` for private source and
`packaging/npm/public-package-contents.json` for staged public source.
`pnpm run pack:clean-room:smoke` regenerates the
archive and runs the complete OD0 npm and pnpm consumer probes on the current CI host.
Unlike `pack:clean-room:check`, smoke mode does not compare or rewrite the retained
exact-environment report, so a Linux run cannot replace the existing Windows evidence
or fail merely because its environment identity is different.

## OCI runtime boundary

The GitLab Dockerfile creates UID/GID `10001:10001`, gives it a writable home, and
sets it as the final image user. The release-artifact workflow builds the candidate
image, verifies both the image configuration and runtime `id -u`, and starts the
bundled adapter through a bounded invalid-input path.

That workflow smoke currently uses a versioned Node base tag only as disposable test
input. It is not a releasable image recipe: a public image still requires a reviewed
base digest, image manifest digest, SBOM/corresponding-source review, and registry
evidence in the later release-integrity gate. GitLab-hosted component execution also
remains independently deferred.

## Offline graph and browser claims

Automated tests prove deterministic self-containment, no network references,
embedded Cytoscape, exact inline CSP hashes, selection/filter/fit controls, keyboard
navigation, and the accessible table fallback. A local manual interaction pass is
retained, but its browser/version was not recorded. Therefore the alpha contract
currently names **no supported browser matrix**. This is `unverified`, not
`unsupported`.

A future named-browser claim must retain browser name/version and operating system,
load the generated file with network unavailable, and exercise Cytoscape rendering,
selection, filters, readable reset, Fit all, keyboard navigation, table fallback, and
CSP console behavior. Evidence from one browser must not be generalized to another.

## Independent provider claims

This gate does not equate related surfaces:

- a local or GitHub-hosted container smoke is not GitLab-hosted component validation;
- the controlled action smoke is not artifact-upload or annotation UI validation;
- mocked comment upsert tests are not real comment mutation; and
- static/browser-contract tests are not a named browser compatibility matrix.

The current labels remain in
[Public identity and alpha surface contract](public-release-boundary.md).
